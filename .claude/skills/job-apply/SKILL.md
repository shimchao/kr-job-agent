# job-apply — 한국형 지원서

글쓰기는 `docs/writing.md`, 절대 규칙은 `CLAUDE.md` 를 따른다. **제출·전송은 사용자가 직접 한다.**

## 0. 시작 문 (하나라도 안 되면 멈춘다)
1. `cv.md`·`config/profile.yml` 이 있고, 이 공고의 `data/reports/` 보고서가 있어야 한다. 보고서가 없으면 `/job-eval` 부터. 보고서의 **「공고 원문」** 이 없으면 사용자에게 공고 본문을 받는다(요약 정보만으로 자소서를 쓰지 않는다).
2. 마감 재확인: `python3 scripts/liveness.py "<링크>"` — `CLOSED` 면 중단하고 알린다. `UNKNOWN` 이면 마감일(공고 원문의 접수기간)만 알려 준다.
3. 현황표 상태가 `지원 안 함`·`마감`·`탈락` 이면 이유를 보여 주고 계속할지 묻는다.

## 0-1. 현직 이직 보호 (`config/profile.yml` 에 `current_employer` 가 있을 때만)
초안을 쓰기 전에 `cv.md` 에서 **현재 회사의 수치·고객·내부 지표**를 뽑아 사용자에게 보여 주고 「외부 지원서에 써도 되는가」를 하나씩 확인한다(`docs/korea-signals.md` §9). 확인 못 한 수치는 쓰지 않고 서술로 바꾼다. 이 확인은 지원서마다 다시 한다.

## 1. 지원 전 결격 질문 점검 (사용자 확인 없이는 쓰지 않는다)
공고 원문에서 아래를 찾아 **원문 그대로 인용**해 사용자에게 보여 주고, 해당 여부를 사용자가 직접 답하게 한다. 내가 추측해서 답하지 않는다.
- 학력·전공 제한 / 병역 요건(필·특례) / 외국어 점수·자격증 필수 / 거주지·근무지 제한 / 입사 가능일 / 우대 사항 중 법정 우대(보훈·장애 등)
- 지원서 양식에 **민감정보 칸**(장애·보훈·가족관계·종교 등)이 있으면, 이는 선택·비선택 모두 **사용자가 그 지원서마다 결정**한다. 이력서에 있다고 자동으로 채우지 않는다. 공고가 이를 요구하는 것처럼 보여도 초안에 쓰지 않는다.
- 직군과 무관한 개인정보(주민번호·가족 직업·재산)를 요구하면 쓰지 않고 「사용자 확인 필요」로 표시한다.

## 2. 갭 확인 대화 (해당하는 갭만, 자동으로 메우지 않는다)
`data/reports/` 의 갭·위험 질문과 결격 점검 결과에서 **실제로 있는 갭만** 사용자에게 묻는다. 선택지: ㉮ 지원서에서 짧게 직접 다룸 ㉯ 언급하지 않음 ㉰ 사용자가 각도를 알려 주면 그대로 씀. 입사 가능일·외국어 수준·직무명 불일치·도메인 불일치가 대표적이다. **사용자가 확인한 것만 쓴다.**

## 3. 네 가지 질문 (자소서 본문을 쓰기 전에 모두 받는다 — 「그냥 써줘」로도 건너뛰지 않는다)
- **A. 왜 이 직무·회사인가** — 공고·회사 정보에서 찾은 각도 4~5개를 보여 주고 1~2개를 고르게 한다(근거는 공고 원문 또는 회사 공식 자료 출처).
- **B. 어떤 문제를 풀겠는가** — 조사 결과 요약을 보여 주고 맞는지 확인(`/job-research` 결과가 있으면 그것을 쓴다. 없으면 회사 공식 자료만으로 WebSearch 2회 이내).
- **C. 입사 첫날 어떻게 접근하겠는가** — 사용자 말로 1~2문장(이게 가장 차별화되는 부분이다).
- **D. 말투** — 격식 / 직설 / 대화체 / 공고 말투에 맞춤.
질문이 없는 자유 양식이면 기본 4항목(지원 동기 · 직무 역량 · 협업·갈등 경험 · 입사 후 포부)으로 쓴다. 지원서 양식의 항목 질문·글자수 제한·글자수 기준(공백 포함/제외)은 이 단계에서 한 번에 받는다.

## 4. 성과 문장 고르기
`cv.md` 에서 모든 불릿을 읽고 공고의 핵심 요구 3~4개와 연결 정도로 점수를 매겨 **항목별 4~5개**를 고른다. `cv.md` 의 **원문 표현과 숫자를 그대로** 쓴다(바꿔 쓰기·반올림 금지, `article-digest.md` 는 맥락 참고용). 공고 단어 맞춤은 숫자가 아니라 주변 어휘에만 적용한다.

## 5. 초안은 대화창에서 먼저 (저장 전에 승인)
항목별 초안을 **대화창에 먼저 보여 준다.** 글자수는 파일로 임시 저장해 직접 센다:
`python3 -c "import sys;t=sys.stdin.read();print(len(t),len(t.replace(' ','').replace('\n','')))" < 파일` — 눈대중 금지, 기준(공백 포함/제외)에 맞춘다.
각 초안 아래에 **근거표**(문장 → `cv.md` 위치 / 공고 원문 위치 / 회사 자료 출처)를 별도로 붙인다. 마지막에 「어떠세요? 승인하시면 저장합니다」. **수정·승인 말이 있기 전에는 파일을 만들지 않는다.** 질문이나 침묵은 승인이 아니다.

## 6. 만드는 것
- **자기소개서** — 항목마다 따로. 항목마다 근거 사실 1~2개. 첫 문장이 결론.
- **경력기술서** — 회사별: 기간 · 직무 · 담당 업무 · 성과(숫자·기간) · 내 역할(주도/참여). 숫자가 `cv.md` 에 없으면 「수치 확인 필요」로 남기고 묻는다. 맞춤 이력서·경력기술서 파일 자체는 `/job-resume`.
- **포트폴리오 구성안** — 가장 가까운 프로젝트 3개와 고른 이유, 장표 흐름(문제 → 내 역할 → 접근 → 결과 → 배운 점). 파일은 만들지 않는다.
- **지원 메일 초안**(요청 시) — 제목·본문·첨부 체크리스트. 보내지 않는다.

## 7. 저장·마무리
1. 승인 후 `data/applications/YYYY-MM-DD_회사_직무/` 에 `자소서.md`, `경력기술서.md`, `포트폴리오-구성.md`, `근거표.md`, 그리고 **지원 시점 스냅샷** `공고-원문.md`(보고서의 공고 원문 복사 + 접수기간)를 저장한다.
2. **제출 전 필수칸 훑기(사용자에게 체크리스트로 준다)**: 지원서 양식의 필수 입력칸 목록 · 첨부 파일 목록 · 글자수 초과 항목 · 민감정보 칸 확인 · 접수 마감 일시. 내가 제출 버튼을 누르지 않는다.
3. 현황표: `python3 scripts/tracker.py set-status <id> "지원서 준비"`. **「지원함」으로 바꾸는 것은 사용자가 지원했다고 말했을 때만** — 그때 `set-status <id> 지원함` 으로 지원일이 기록되고 팔로업 시점이 계산된다.
4. 끝에 「확인 안 된 것」(수치 미확인 항목, 글자수 기준 가정, 근거가 약한 문장, 회사 정보 출처 한계) 최대 3개.
