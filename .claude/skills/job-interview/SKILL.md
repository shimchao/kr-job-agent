# job-interview — 계획 · 연습 · 복기

공통 규칙: ① `cv.md`·`article-digest.md`·`data/interview-prep/story-bank.md` 에 있는 사실만 쓴다. 답변 개선안도 **사용자가 말했거나 파일에 있는 사실만** 쓴다(프레이밍을 다듬는 것이 일이고 경험·숫자를 보태는 것은 날조다). ② 사용자가 연습 중 「그건 증명 못 해요」라고 인정한 주장은 `data/interview-prep/retracted-claims.md` 에 적어도 되는지 묻고, 이후 연습에서 다시 쓰지 않는다. ③ 파일 위치: `data/interview-prep/`.

## 1. plan — 면접 준비 계획
입력: 회사·직무(보고서 `id`), 면접 날짜, 라운드(서류 → 인사담당 전화 → 실무면접 → 임원면접 → 최종), 남은 준비 시간.
1. **적합도 점검**: 보고서의 갭을 읽고 이번 라운드가 어디를 찌를지 예상한다.
2. **라운드 정보**: 회사 공식 채용 페이지·보도·후기에서 **확인된** 라운드 구성·형식(인성·직무·PT·과제)만 쓴다. 후기는 표본 수·시기를 같이 적고 일반화하지 않는다.
3. **시간 블록 계획**: 남은 시간을 [자료 읽기 · 스토리 정리 · 말로 연습 · 질문 준비]로 나눈 표(블록별 산출물 1개씩).
4. **핵심 한 장**: 예상 질문 10개와 각 질문에 쓸 스토리·첫 문장 · 역질문 5개(`docs` 가 아닌 회사 자료에서 나온 것) · 면접 직전 15분 점검표.
5. 저장: `data/interview-prep/{회사}-plan.md`.

## 2. practice — 모의면접
시작 전 `story-bank.md`·보고서가 있는지 확인하고, 없으면 `/job-eval` 의 F칸부터 안내한다.
- 면접관 역할을 맡는다: 「한 번에 질문 하나씩 합니다. 실제처럼 답하세요. '멈춤'이라고 하면 피드백을 먼저 드립니다.」 인사 없이 첫 질문부터.
- **답변이 끝나면 피드백**(말로 연기를 깨고):
  - **잘된 점** — 사용자가 한 말을 인용해서
  - **다듬을 점** 1~2개 — 빠진 것·모호한 표현
  - **더 나은 한두 문장** — 사용자가 말한 사실만으로
  - **상태**: ✅ 강함 / 🟡 무난 / 🔴 갭
- 이어서 꼬리질문 1개(답이 부족하면 실마리를 끌어내고, 강하면 더 깊게). 같은 사례를 두 번째 쓰면 짚는다(「사례가 같습니다. 다른 사례는 없나요?」).
- 행동 면접 답변에는 **돌아본 점**(지금 다시 한다면)이 있는지 본다. 없으면 한 번만 묻는다.
- 답이 2분(글로 하면 길어 보이는 정도)을 넘으면 「결론을 앞에 두기」를 권한다. 내용을 자르는 게 아니라 순서를 바꾸는 문제다.
- **정직하게.** 「좋은 답변이에요」처럼 내용 없는 칭찬은 하지 않는다. 약하면 약하다고 이유와 함께 말한다.
- 사용자가 모르는 회사 정보를 묻는 질문에서 막히면 연기를 멈추고 그 질문에 한해 조사한 뒤 출처와 함께 알려 준다. 지어내지 않는다.
- 라운드별 질문 세트: 인사담당 전화(지원 동기·이직 사유·희망 연봉·입사 가능일·근무 조건) / 실무 면접(직무 사례·의사결정·지표·갈등·실패) / 임원 면접(방향성·조직 기여·리더십·장기 계획) / PT·케이스 면접(문제 정의 → 접근 → 결과). 질문은 공고·보고서의 갭에서 뽑는다.
- 끝나면 세션 요약(질문별 상태, 반복 사례, 가장 약한 3개, 다음 연습 과제)을 보여 주고 `data/interview-prep/{회사}-practice-{날짜}.md` 에 저장한다.

## 3. debrief — 면접 직후 복기
면접 직후(기억이 남아 있을 때) 하는 것: 
1. **받은 질문 기록**: 사용자가 기억나는 대로 말하게 하고 질문별로 `질문 · 내가 한 답 · 면접관 반응`을 정리한다.
2. **사실 충돌 확인**: 사용자가 면접에서 말한 사실이 `cv.md` 와 다르면(숫자·직급·기간) 그 자리에서 알려 준다. 지원서 쪽이 틀렸는지 면접 답이 틀렸는지는 사용자가 정한다.
3. **질문별 솔직한 평가**: 잘 답한 것 / 부족했던 것 / 몰랐던 것.
4. **질문 은행 갱신**: 새로 받은 질문을 `data/interview-prep/question-bank.md` 에 추가(중복 제외).
5. **갭 메우기**: 몰랐던 것의 정확한 답을 찾아 정리(출처 포함).
6. **새 스토리 추출**: 면접 중 나온 경험이 `story-bank.md` 에 없으면 사용자 말로 추가.
7. **다음 라운드 정보**: 면접관이 알려 준 프로세스·일정·평가 포인트를 사실로만 기록.
8. **합격 가능성(선택)**: 사용자가 원할 때만. 근거 목록과 함께 「가능성이 높아 보임/불확실/낮아 보임」 정도로, 숫자 확률을 만들지 않는다.
9. 저장: `data/interview-prep/{회사}-debrief-{라운드}-{날짜}.md`. 현황표 상태가 다르면 `set-status` 를 제안한다(변경은 사용자 확인 후).
