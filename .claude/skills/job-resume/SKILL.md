# job-resume — 공고별 맞춤 이력서

글쓰기는 `docs/writing.md`, 규칙은 `CLAUDE.md`. **`cv.md` 자체는 고치지 않는다.** 맞춤본은 별도 파일이다.

## 순서
1. `cv.md`·`config/profile.yml`·해당 공고 보고서(`data/reports/`)를 읽는다. 보고서가 없으면 `/job-eval` 먼저. 보고서의 E칸(맞춤 계획)과 B칸(핵심 요건)이 이 작업의 기준이다.
1-1. `current_employer` 가 있으면 현재 회사의 수치·내부 지표를 사용자에게 보여 주고 이 맞춤본에 써도 되는지 확인한다(`docs/korea-signals.md` §9). 확인 못 한 수치는 맞춤본에서 뺀다. `cv.md` 자체는 그대로 둔다.
2. **재배열·강조만 한다.** 허용: 요약 문장 재작성(사실 범위 안에서) · 불릿 순서 변경 · 공고에 가까운 경험을 위로 · 공고 용어와 같은 의미의 내 표현을 공고 용어로 바꾸기(같은 의미일 때만). 금지: 없는 경험·숫자·도구·직함 추가, 기간·직급 변경, 「만든 것」과 「쓴 것」 혼동.
3. **키워드 점검**: `python3 scripts/keyword_match.py --jd <공고원문파일> --cv <맞춤본.md>` 로 점검하고 「없음」 단어는 **실제로 한 경험일 때만** 사용자에게 확인 후 보강한다.
4. 초안을 **대화창에서 먼저** 보여 주고 사용자가 승인한 뒤에만 파일로 저장한다(질문·침묵은 승인 아님). 바뀐 부분은 `cv.md` 대비 변경 목록(무엇을 위로/아래로/바꿨는지)으로 같이 보여 준다.
5. 저장: `data/applications/{날짜_회사_직무}/이력서-맞춤.md`. 인쇄용 HTML·PDF가 필요하면 `python3 scripts/render_pdf.py <맞춤본.md>` (크롬이 있을 때). 생성한 PDF를 열어 **글자 깨짐·페이지 넘침**을 확인한 뒤 알려 준다. 열어 보지 못했으면 못 봤다고 쓴다.
6. 한국 양식 안내: 정해진 사이트 이력서 양식(사람인·잡코리아 이력서 등)에 직접 입력하는 경우엔 이 맞춤본의 문장을 복사해 쓰도록 항목 대응표를 만든다. 사진·생년월일·가족관계 같은 항목은 사용자가 원할 때만 다루고, 요구되는지 공고에서 먼저 확인한다.
7. 끝에 「확인 안 된 것」 최대 3개.
